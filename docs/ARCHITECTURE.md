# Архитектура

## Слои

```
shared/       — общий модуль правил: типы состояния, команды, события, чистая игровая логика, RNG.
                Используется и сервером, и клиентом (для мгновенного отклика интерфейса).
server/       — авторитетный сервер: хранит мир, принимает команды, применяет правила,
                рассылает события обоим игрокам, тикает игровое время, хранит в SQLite.
client/       — интерфейс: отображение и ввод, адаптивный (телефон + компьютер).
content/      — данные: предметы, здания, локации, враги, диалоги, события, тексты (на украинском).
content/secret/ — сюжетная библия, план актов, граф раскрытий, статус (см. README там).
tests/        — включая боты-клиенты для автопрохождения за двоих.
deploy/       — Dockerfile, docker-compose.yml.
DEPLOY.md     — инструкция для игроков.
```

Движок не знает про конкретный сюжет. Сюжет живёт в данных.

## Поток команд

```
клиент игрока A ──команда──► сервер ──проверка правил──► новое состояние ──событие──► оба клиента
```

Клиент никогда не меняет мир сам. Сервер проверяет каждую команду: можно ли это сделать, онлайн ли нужные игроки, не идёт ли совместная сцена.

## Совместные сцены

У сюжетного контента есть требование присутствия:

- `solo` — может делать любой игрок, даже если второй офлайн (только рутина в открытом контенте);
- `together` — нужны оба онлайн; оба подтверждают готовность, и сцена начинается.

Совместная сцена — это состояние на сервере. Если кто-то отключился, сцена ставится на паузу и продолжается с того же места.

## Системы: начинать с малого

Для первого акта обычно хватает:

- ресурсы и две разные роли сбора;
- одно-два здания;
- общий костёр / отдых как место совместных моментов;
- исследование локаций;
- один NPC с диалогом;
- сохранение мира.

Крафт, экипировка, бой, поселение, фракции и прочее вводи, когда для них появляется сюжетная или игровая причина.

## Состояние мира

```
WorldState
  meta          — версия, сид, игровое время
  players[2]    — персонаж, роль, онлайн/офлайн, личные открытия
  world
  settlement
  inventory     — общий склад + личное, если нужно
  relationships
  quests
  discoveries   — общие открытия
  narrative     — сюжетные флаги, прогресс, текущая совместная сцена
  flags
```

Системы не меняют чужие части состояния напрямую — только через команды и события. Сюжетная система слушает игровые события, а не вшивается в каждую механику.

## Личная и общая информация

Каждое открытие помечено: видно обоим или только одному игроку. Сервер отправляет клиенту только то, что этот игрок должен видеть. Не отправляй на клиент чужие личные улики «скрытыми» — их можно подсмотреть.

## Сюжетное состояние

Разделяй:

- **правду** — как всё на самом деле (в `content/secret/`);
- **обнаруженное** — какие улики нашёл каждый игрок;
- **уровень понимания**: НЕИЗВЕСТНО → ЗАМЕЧЕНО → ПОДОЗРИТЕЛЬНО → ЧАСТИЧНО ПОНЯТО → РАСКРЫТО.

## Хранение и миграции

Мир хранится в SQLite в томе Docker, чтобы переживать перезапуски и обновления. Миграции — с первого дня. В `DEPLOY.md` — как сделать резервную копию мира перед обновлением.

## Вёрстка

- Сначала мобильная вертикальная вёрстка, потом расширение для компьютера.
- Крупные кнопки, читаемый текст, без горизонтальной прокрутки.
- Всё, что видно при наведении мыши, должно быть доступно и нажатием.
- Понятно видно, что делает второй игрок и онлайн ли он.

## ID

Стабильные и нейтральные: `loc_07`, `npc_03`, `item_12`, `secret_05`. Отображаемые названия — в данных, отдельно от ID.

## Валидация контента

Автоматически проверяй: дубли ID, битые ссылки, недостижимые локации, квесты и концовки, циклические и невыполнимые условия, некорректные стоимости, ссылки в диалогах, условия раскрытия тайн, корректность требований `solo` / `together`, наличие украинского текста для каждого ключа.
